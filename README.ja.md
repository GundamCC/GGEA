## 主な機能

- **デイリータスク**：戦艦の回収、ショップの無料デイリーパック購入、開発・強化各1回、強化育成ステージのスキップ、AP消費、報酬受け取りに対応。ドラッグで実行順序を変更できます。
- **報酬受け取り**：プレゼントとデイリーミッション報酬を受け取ります。設定により、ほかのデイリータスク完了後に最終報酬を受け取れます。
- **AP消費**：メインステージの作品とHARDステージを指定してスキップします。実行順序の変更と設定の保存に対応しています。
- **自動周回**：指定ステージを繰り返しプレイします。周回数や特定の状況での出撃を設定できます。
- **自動スカウト**：スカウト可能なキャラクターを自動でスカウトします。
- **自動攻略**：メインステージのHARDまでの進行、ヒストリーステージ（BOSSを含む）、強敵襲来の3難易度に対応しています。
- **強敵襲来**：毎日の強敵襲来をスキップします。デイリータスクにも追加できます。
- **マスターリーグ**：マスターリーグに自動で挑戦します。リザルト後、45秒以内に2回、5人全員への勝利を確認すると、その結果を保持します。短い待機中に昇格案内が表示された場合は処理を続け、それ以外は自動終了します。マスターリーグでは対戦前に選択中の相手を確認し、リザルト後に5枠の状態を記録します。復旧確認後も選択を確認できない場合や、挑戦済みの相手が0ポイントのままで次の候補がない場合は停止します。
- **ボール工場**：指定したGPを獲得するまで、ボールの生産と解体を繰り返します。

## はじめに

### ダウンロード

[GitHub Releases](https://github.com/GundamCC/GGEA-SD-Gundam-G-Generation-Eternal-Assistant/releases) から正式版をダウンロードしてください。主リポジトリに正式版がまだない場合は、[旧版の互換ダウンロード](https://github.com/GundamCC/GGEA-Release/releases)を利用してください。ソースの更新と正式パッケージの公開は別です。

### 使い方

1. ゲームをインストールしたAndroidエミュレーターを起動し、下記のいずれかの横画面設定を選び、ADBデバッグを有効にします。
2. ZIPファイルをすべて展開し、フォルダー内の `GGEA.exe` を起動します。実行ファイルだけを別の場所へ移動しないでください。
3. 右上の設定（「设置」）で、使用するエミュレーターの `adb.exe` を選択します。BlueStacksでは `HD-Adb.exe` を選択してください。
4. 設定でゲームのサーバーと言語を選択して保存します。メイン画面で更新（「刷新」）を押し、操作対象のエミュレーターを選択します。
5. ゲーム内のアカウントと画面を確認してから、必要な機能を選択してタスクを開始します。

VC++ v14 x64 ランタイムは別途必要です。現在のソースでは起動時の検査と `DependencySetup_依赖库安装.bat` の同梱に対応しています。旧パッケージにスクリプトがない場合は [Microsoft](https://aka.ms/vc14/vc_redist.x64.exe) から入手してください。[インストール手順](https://www.gundamc.com/ggea/docs/ja/guide/install/)と実際のリリース内容を確認してください。

## 注意事項

- 推奨エミュレーターはMuMuまたはLDPlayerです。
- 対応サーバー：グローバル版、日本版。
- 対応するゲーム内言語：簡体字中国語、日本語。これはGGEA自体の表示言語とは異なります。
- 動作確認済みのエミュレーター：MuMu 6、MuMu 12、LDPlayer 14、BlueStacks 5。環境によって動作が異なる場合があります。
- 対応OS：Windows 10/11 x64。配布パッケージには.NETランタイムが含まれており、別途インストールする必要はありません。
- ソース版 v1.4.15.0：メインステージとヒストリーステージの作品ロゴを `resources/common/templates/logo/` にまとめました。旧設定の既定パスは自動的に切り替わります。
- ソース版 v1.4.14.0：期間限定イベントにステージ攻略とデイリーステージ10回を追加しました。デイリーステージ、ミッション報酬の受け取り、BOSS バトル、メダルユニット補給を選択して、1件のデイリータスクに登録できます。期間限定イベントの BOSS 戦闘タイトルの認識しきい値を 0.90 に調整しました。期間限定イベントの簡体字中国語テンプレート全33枚を、MuMuの1920×1080のゲーム画面から再取得しました。BOSS スキップでは画面が安定するのを待ち、入口、ステージボタン、チケットダイアログを連続する2枚の画面で確認してから操作します。各回の獲得数を確認したら結果を閉じ、補給画面右側の一括交換ボタンに表示された費用から今回の回数を確認します。1回につき5枚を消費し、ボタンがグレーになると終了します。メダルユニット補給画面からも自動交換を開始できます。ゲームでストーリーイベントまたは BOSS バトル画面を開き、アシスタントの「期間限定イベント」で常設 BOSS の難易度（初期値 EXPERT）を選んで開始します。精算のたびにレア BOSS を確認し、出現中なら1回、通常は選択した難易度を最大回数スキップします。チケット不足時はダイアログを閉じて終了します。
- ソース版 v1.4.5.4：デイリーの開発・強化で機体候補の検出から0.5秒後に再確認します。開発タイトル全体が一致しない場合は、同じ位置で文字を照合します。タイトルと機体の位置を確認してからタップします。
- ソース版 v1.4.5.3：ゲーム画面の照会には設定済みの ADB コマンドタイムアウトを使用します。画面照会が1.5秒を超えるとAP消費が中断する場合がある問題を修正しました。
- ソース版 v1.4.3.2 では、メインウィンドウのコードを機能別に整理し、デイリータスクと AP 消費のリストで並べ替え処理を共通化しました。
- 設定画面では変更した項目だけを保存します。複数のウィンドウで同じ項目の変更が競合した場合は、設定を開き直してください。
- 同じフォルダーの `GGEA.exe` を再度起動すると新しいウィンドウが開きます。同じ端末でタスクが実行中の場合は、別のウィンドウで開始すると使用中と表示されます。異なる端末では並行して実行できます。設定ファイルは共通です。更新をインストールする前に他のウィンドウを閉じてください。
- 複数のエミュレーターを切り替えて使用できます。ソース版 v1.4.0.5 では、開始時に選択した端末の接続を確認します。終了や再起動を知らせるメッセージが出たら、更新された一覧で対象の端末を選び直してください。
- 開発ロードマップと戦艦エリアの検索では、指を終点で短く止めてから離します。開発版の「画面取得と操作」では始点・終点・時間を指定して「精密ドラッグ」を試せます。初回は同梱の入力コンポーネントを ADB 経由で選択中の端末に転送します。
- 開発版の「画面取得と操作」で「ミッション画面を開く」を選ぶと、横画面 16:9 のホームまたはステージメニューからミッションを開きます。ステージメニューでは一度ホームに戻り、すでにミッション画面なら確認だけで終了します。
- 自動操作は現在 1280×720（240 DPI）、1600×900（240 DPI）、1920×1080（280 DPI）、2560×1440（320 DPI） の4種類の横画面設定に対応しています。タスク、OCR、デバッグ操作の基準座標は全設定共通で 1920×1080 です。画面認識と入力位置は端末のスクリーンショットサイズに合わせて変換されます。
- AP消費プランは `config/ap_consumption_profiles.json` に保存されます。
- 初回は動作を見守りながら使用してください。ダイヤ消費、課金、認証、想定外の画面が表示された場合は停止して手動で確認してください。

## ダウンロードファイルの確認

Releaseには、ZIPと同名の `.zip.sha256` ファイルも添付されています。以下のファイル名を、ダウンロードしたZIPの名前に置き換えて実行してください。

```powershell
(Get-FileHash -Algorithm SHA256 -LiteralPath '.\<ダウンロードしたZIPのファイル名>').Hash.ToLowerInvariant()
```

出力された値が `.zip.sha256` の先頭列と一致することを確認します。パッケージ内の `build-info.json` にはソースのコミットとファイルのハッシュが記録されています。SHA-256はファイルの整合性確認用であり、電子署名ではありません。

## 使用しているプロジェクト

- [.NET 8](https://dotnet.microsoft.com/en-us/) / [WPF](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/)：WindowsアプリケーションとUI。正式版は自己完結型で配布されます。
- [OpenCvSharp 4.13.0.20260627](https://github.com/shimat/opencvsharp) / [OpenCV 4.13.0](https://opencv.org/)：画像の読み込みとテンプレートマッチング。`OpenCvSharpExtern.dll` はパッケージに同梱されています。
- [ONNX Runtime 1.23.2](https://github.com/microsoft/onnxruntime) / [PaddleOCR PP-OCRv5](https://github.com/PaddlePaddle/PaddleOCR)：ローカルCPUでステージ番号とHARDの見出しを認識します。モデルとライセンスは `resources/common/ocr/` を参照してください。
- [Android Debug Bridge (ADB)](https://developer.android.com/tools/adb)：エミュレーターへの接続、スクリーンショット取得、操作の送信に使用します。ADBは同梱されていません。エミュレーター付属のADBまたはAndroid SDK Platform-Toolsを使用してください。

現在のソースでは、タスク実行・設定・画像認識を独立した `net8.0` コアに分離しています。Windows アプリは引き続き WPF を使用し、macOS UI はまだ組み込まれていません。[開発ガイド](docs/development.md#核心与平台边界)を参照してください。

現在のソースでは、認識診断にホストの製品バージョンを記録し、リソースパスの比較を実行プラットフォームに合わせています。灰色の「一括開発」ボタンは短い間隔で再確認し、連続2フレームの確認とキャンセル条件を維持します。
