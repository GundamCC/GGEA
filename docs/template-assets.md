# 游戏识别素材开发指南

开发或采集识别素材前，先在 `resources/common/templates` 和当前游戏语言的模板目录中按控件用途查找，再检查已有调用方。用目标页面的实际截图、项目匹配器和生产搜索区域验证候选素材。相同控件跨页面复用同一逻辑路径，页面差异由标题、按钮状态和搜索区域区分。

| 识别对象 | 逻辑路径示例 | 用法 |
| --- | --- | --- |
| 关闭按钮 | `resources/templates/common/close.png` | 在已确认的弹窗或结果页底部搜索 |
| OK 按钮 | `resources/templates/dialog/button_ok.png` | 先确认弹窗标题及操作含义，再匹配 OK |
| 仅在活动中出现的简体中文标题 | `resources/templates/stage/event/limited_time_event/medal_supply_title.png` | 采集到 `resources/zh-CN/templates/stage/event/limited_time_event/` |

## 目录与回退

业务代码引用 `resources/templates/…` 逻辑路径，通过项目的资源解析和匹配入口读取。资源语言取自游戏语言设置。对同一相对路径，解析器优先选择当前语言，模板匹配可继续尝试 common 候选。其他语言目录不参与回退。

已有按钮能匹配时直接复用。确有语言差异且实测需要覆盖时，将变体放到 `resources/<游戏语言>/templates/` 的相同相对路径。新采集的简体中文文字素材放到 zh-CN。将素材作为跨语言通用件时，保留能验证其适用画面的证据。界面翻译与游戏截图的语言配置分别管理。

## 采集与核对

采集前先定位游戏显示屏，读取原始 PNG 的宽高，确认基准素材来自原生 1920×1080 画面。其他分辨率截图保留原尺寸作为兼容性样本。限时活动 BOSS 战斗标题在启动、关卡列表和结算返回时统一使用 0.90 阈值。

- 模板采用助手的 1920×1080 识别尺度，裁剪稳定的字形或图标。余额、数量、奖池分母和倒计时使用相应区域的 OCR 或已有像素判定。
- 页面标题与动作分开验证。对重置、兑换等有消耗的操作，在同帧确认页面和可用状态，并在下一帧核对操作结果。
- 用实机样本覆盖命中、相似按钮、置灰状态及实际点击位置。整页取证图和带动态数值的样本用于回放，发布目录只收录运行所需的识别素材。
- 合并重复素材时检索源码、配置、测试和文档中的引用，切换到共享路径并回放原页面，最后删除重复文件。

## 裁剪、搜索区域与点击中心

同一段文字的紧裁剪和整个按钮外框占用不同尺寸。更换素材时，同时核对 PNG 像素宽高、透明遮罩、搜索区域及点击中心。ROI 要能完整容纳模板，并留出实测位置波动的余量。按钮外框、发光、动效、邻行文字及滚动边缘都可能影响匹配分数。搜索区过宽也可能把相邻的另一个按钮选为目标。

用实机画面归一化到项目坐标系后，通过生产匹配入口回放。记录期望的点击范围，检查实际命中框和中心；对靠近边缘的按钮加测上下左右偏移，例如 10 px。偏移量来自本次验证，不代表所有素材都有同样的容差。用置灰、遮罩和相邻按钮画面复核拒绝路径。若失败，先检查缩放、裁剪、遮罩与 ROI，再考虑阈值。

素材命中还须结合当前任务阶段。开发页面等待与恢复时，参照[任务阶段恢复](global-screen-handling.md#任务阶段恢复)，用连续新帧及业务进度核对操作时机。

动态场景应在限定时间内反复截图。入口标题、可操作按钮及弹窗状态应在相邻两帧一致，按钮位置稳定后才点击。转场中的单帧未命中继续等待，重新识别期间只读观察。

## 强化列表的排序方向

各入口共用 `Tasks/Upgrade/UpgradeListService`。在已确认的强化列表上调用 `EnsureDirectionAsync` 可保持或反转当前排序，当前排序字段由游戏保留。从「强化部队」委托进入时，游戏默认按 LV 排序。助手通过方向图标确认升序，核对筛选已开启后选择首台机体。若卡片的 LV 标签素材未命中，则用英文及数字 OCR 读取首卡等级行。右下角相邻的蓝色筛选控件与方向按钮分别定位。

## 单位强化材料与角色报告

角色详情先匹配标题。调度资金跳过立绘；强化部队确认标题后再比对立绘，用数字 OCR 识别标题编号和进度。表格 2.8.1 收录 54 名角色的 144 条基本强化委托。「强化部队6」需要 5 份，编号和消耗量分别读取。配置位于 `resources/common/data/strengthen_requests.json`，使用 `tools/export-strengthen-requests.py 工作簿 图片核对.csv 输出文件` 再生成。

「提升LV」弹窗的铜、银、金对应 R、SR、SSR，资源来自主数据 `m_item` 的 `uexp_0001`、`uexp_0002`、`uexp_0003`，在 `resources/common/templates/upgrade/` 保留精灵原图。MuMu 1920×1080 的三个栏位自左向右是金、银、铜。通过图标内部纹理确认材料，数字 OCR 读取每栏的已选数和库存。游戏的预选计入总数，每次加减后核对三栏；仅在份数完全相符时发送一次「提升LV」。缺料时取消预览，回到原角色记录失败。提交后若出现「LV UP 完成」，确认 TAP TO NEXT 再点击。经验不足以升级时会直接返回单位资料，连续两帧核对资料标题和返回按钮后沿原路退出。

按原路回到同一角色和委托，核对进度满额及橙色「报告」。报告对话按[角色要求开发约束](character-requests.md)推进至返回列表。遇到「回报完成」点中央，「领取结果」点 OK；回到角色列表且该栏进入刷新倒计时后计入已报告。刷新文案只取固定的「距离更新」，排除剩余小时数。

## 委托作品、角色与开发起点

`resources/common/data/character_request_index.json` 按 ID 保存作品、角色、机体与委托。角色和机体的 `SeriesIds` 保留主数据中的全部作品归属，每条委托的 `SeriesId` 单独保存其目标作品。2.8.1 的 1,046 条委托包含 74 个角色 ID 和 387 个指定机体 ID。共享立绘去重后为 68 张，补入路线起点后共 400 张单位图。

使用同版工作簿、含 `已解析主数据` 与 `OCTO美术` 的快照，在仓库根目录运行 `python tools/export-character-request-index.py 工作簿 快照目录 resources/common`。脚本使用 openpyxl 和 Pillow。角色原图取自 `m_character` 的 `cb_` 精灵，保存在 `base/character_requests/portraits/`。路线图机体取自 `m_unit` 棋子键对应的 `ogk_` 精灵，保存在 `develop/dev_unit/`，保留原始方向与透明通道。

`series_development_bases.json` 记录 32 个开发作品默认路线图的起点、节点位置、单价和材料。优先选属于目标作品且无前置节点的机体，再依次比较额外材料、CAPITAL 和列位置。同等条件下优先采用该作品角色的「交付机体1」，再按行与单位 ID 确定。普通开发委托涉及其中 19 个作品，全部可仅用 CAPITAL 开发。其余路线也保留真实起点和费用。若一张图没有标记为该作品的根节点，基准表记录图上的起点，机体的作品归属仍以主数据为准。《机动战士V高达》的基准为杰姆兹刚（4,000 CAPITAL），《机动战士高达》的基准为 61 式战车（1,000 CAPITAL）。

简中详情用 `title_development.png` 匹配固定标题，用数字 OCR 读取编号和进度。开发入口沿用共用路线图搜索，优先向左侧查找，在两帧稳定识别同一机体后打开批量开发。按剩余数量设置，连续两帧核对 `develop/capital_only.png`、数量、总价与余额，完成后返回原角色核对满额进度并报告。

`series_development_bases.json` 记录 32 个作品、60 张分图及其顺序。`develop/series/logo_s_series_*.png` 和 `develop/tabs/ui_developtree_tabbanner_*.png` 均为 2.8.1 原生 Sprite。开发列表按 1920×1080 的五列卡片布局匹配，使用 0.640、0.643、0.646 三档缩放，排除透明背景。雷霆宙域两部作品另在同一位置比对竞争 Logo。实机列表截图覆盖 28 个作品。其余 4 个作品（240、2170、3360、3760）已校验主数据映射、原生素材，以及未出现时不会在样本中误命中。

图上页签以原生色板和两侧纹理定位，中间的本地化文字及 COMPLETE 标识不参与匹配。点击后连续两帧核对同一页签右边框点亮。分图编号按主数据展示顺序取值，例如 SEED DESTINY 的第一、第二张普通图依次为 133002、133001。交付依据目标机体直接选分图。开发与铁球工厂的随包入口按作品 Logo 选择，未知机体依次搜索该作品的普通分图。自定义入口模板仍使用原配置。

交付窗口使用游戏筛选后的卡片，只按卡框位置、LV、突破星数和锁定状态选择。卡片锁标记 `delivery_card_lock.png` 取自 MuMu 1920×1080 的 (1001,596,35,28)，在卡片右侧搜索，阈值 0.94。库存从底部向上检查，只有完整查找后仍无合格单位才补开发。模糊的选中状态或未能读取的候选等级不能授权开发。预览核对一台、成品等级、整线总价和余额，执行按钮就绪后才发起开发。按设备、栏位、角色、委托编号和 8 小时刷新期记录消费尝试，重跑先找库存。返回后须确认原角色、原编号及单台选择保护，再进入交付结算。

## 请求出击与标准关卡略过

简中标题 `base/character_requests/title_sortie_request.png` 裁自原生 1920×1080 画面，范围为 (1404,247,133,33)。搜索区为 (1340,225,300,80)，阈值 0.96。仅裁固定字样，右侧编号和条件下方的进度使用数字 OCR，再与角色及委托表核对。莎蒂·卡伦「请求出击2」的挑战和报告两页分别识别为 0/2 和 2/2。

标准选关页使用当前语言的选关标题。体力框可显示超过自然恢复上限的值；所需 AP 来自当前选中的关卡。标准略过弹窗按红色下降箭头右侧的数字读取预计余额，箭头会随位数移动。调数后需确认当前体力减去单价乘次数，等于弹窗预计余额。部分略过返回时按关卡剩余次数的实际减量确认；次数用尽时也可通过原有次数上限按钮核对。

### 战舰巡航返回基地
