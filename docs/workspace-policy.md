# GGEA 多仓库工作约定

## 工作区与仓库职责

本目录只组织四个独立 Git 仓库，不在父目录初始化 Git。每次操作前确认实际工作目录、Git 根目录、分支、远程、暂存区和已有改动；不得沿用旧聊天目录或从父目录执行提交。

| 子目录 | 职责 | 同步检查对象 |
| --- | --- | --- |
| GGEA | Windows 主程序、公共插件协议、配置、识别资源与测试 | 网站操作说明、发行说明、扩展兼容性 |
| GGEA-Extensions | 可选插件、独立版本及其安装和恢复流程 | 主程序协议、插件文档、网站插件说明 |
| GGEA-Release | 已发布包的说明、下载入口、校验信息 | 已验证产物、源码提交、网站下载数据 |
| GGEA-website | 官网、使用文档与下载展示 | 主程序真实行为、扩展安装要求、实际 Release |

旧仓库仅作历史归档，不再开发、打包或作为版本来源。未明确授权，不修改其他仓库或恢复旧仓库维护。

## 每次改动的跨仓库影响检查

开始前明确主改仓库，并逐一判断其余三个仓库是否受到影响。检查功能入口、设置默认值、文件路径、接口/API、配置迁移、最低兼容版本、安装依赖、资源与许可、下载及发布信息。说明具体影响或“无影响”的原因，不因是文档改动就跳过影响检查。

必要的兼容修正和直接相关文档同步属于同一任务，应在交付前完成；不能只改一端后留下失效入口。涉及破坏性接口、迁移、发布或外部权限时遵守用户授权。跨仓库不等于默认执行所有仓库的构建或测试。

## README 与文档同步

- 每次更新检查主程序 README、离线使用说明、CHANGELOG、RELEASE，网站对应功能页和导航、发行仓库 README（含已有语言版本）、扩展 README。只修改实际受影响内容；内部实现调整可说明无需更新用户文档的理由。
- 主程序 README 以发行仓库既有介绍结构为基础，保留 GGEA 的功能、下载、社区和使用入口；开发入口与源码许可是补充。详细步骤放文档站或离线说明，不堆入 README。
- 文档只写本项目事实，不加入外部项目对比、参考过程、AI 工作过程或未经验证的兼容承诺；真实依赖、第三方许可和必要来源声明必须保留。
- 功能、设置、默认值、限制与失败行为变化时同步使用说明和网站相应页面；中日文已有同类说明应一并检查，不能留下相互矛盾的描述。
- 主程序产品版本唯一来源是 GGEA/src/GGEA.App/GGEA.App.csproj。版本变化在同一任务同步主程序 README、RELEASE.txt、使用说明.txt、CHANGELOG.md，并执行 Get-ReleaseVersion；纯文档不加产品版本。
- 源码版本、已发布版本、已部署网站分别记录。未生成和验证正式包前不得更新发行仓库或网站为“已发布”，不得猜测下载地址、摘要或兼容版本。文档可说明尚未发布的源码变化。
- 扩展版本由扩展项目自身维护，核对 manifest 与宿主 API 兼容性；网站改动不递增桌面或扩展版本。

## 验证、提交与交付

根据影响运行必要检查：程序按本仓库约定 Build 一次并合并冒烟和相关测试；扩展验证受影响接口和独立构建；网站验证相关链接、内容、类型和构建，视觉改动需实际预览；发行变更核验真实产物、摘要和版本。纯文档执行链接、版本（适用时）、Diff 和敏感信息检查，不机械重跑程序测试。

各仓库独立审查、显式暂存、本地提交；保护其他任务改动。不因一个仓库获准 Push 就推送其他仓库。默认不 Push、不部署、不创建 Release，用户本次明确授权的例外按范围执行。不得跨库复制私有配置、凭证、日志或用户截图到公共仓库。

交付简洁列出四个仓库的影响、已改文件与未改理由、验证结果、提交/推送状态及待发布事项；如一个必要同步仍受阻，明确报告，不称完整完成。
