# 角色要求开发约束

修改每日任务入口、个人基地导航、委托识别、强化、开发、交付或报告流程时，先核对本页。委托表或流程发生变化时，同步维护本页、相关回放和用户说明。素材裁剪范围与阈值见[游戏识别素材开发指南](template-assets.md)，转场等待见[任务阶段恢复](global-screen-handling.md)。

## 入口、栏位与刷新

- 每日「角色要求（个人基地）」在简中默认勾选。用户可以取消。设置页「角色要求」位于「自动推图」右侧。
- 战舰回收后接续执行时，从巡航详情返回基地，优先向地图右侧搜索一次。场景飞行物会遮挡入口，巡航和角色要求按钮都要连续三帧确认位置。
- 每天北京时间 00:00、08:00、16:00 三栏同时刷新。跨刷新期重新确认栏位、角色和委托。补开发前后的校验与消费记录必须使用同一刷新期。
- 列表逐栏用英文 OCR 读完整的 RANK，白锁复用通用锁素材，刷新提示表示该栏已完成。连续两帧确认栏位状态且彼此不冲突后才打开。第三栏锁定时最多处理前两人，本轮上限只可缩小。

## 识别、承接与报告

- 先识别任务标题，再按任务类型识别角色立绘。调度资金跳过立绘。标题、按钮用当前语言的素材，OCR 限英文、数字和数值分隔符。编号、要求数量和已完成进度分别读取。
- 按委托 ID 关联角色、作品和机体。强化或开发的目标作品取委托条件中的作品 ID。作品可能有多张路线图，单位素材使用路线图里朝左的小机体图。查找基准节点时优先左侧，往返扫描相邻行或列，换行后从当前侧继续。更新表格或 ID 映射时同步更新生成规则、JSON 和引用的素材。
- 各类型共用承接流程。确认「承接」后，反复点击中央推进台词和预告，回到要求列表或详情即停止。需要继续执行时打开原栏并核对当前动作。报告或交付后按已确认的奖励按钮领奖，回到列表且原栏转为刷新状态才计为完成。
- 页面、角色、动作或资源消耗无法核对时停止相应动作。可确认的缺料、无合格单位和未完成按该栏记录，已知返回页再处理下一栏。

## 普通委托

| 类型 | 执行条件与行为 |
| --- | --- |
| 强化部队 | 按角色、编号和进度查剩余材料份数。挑战直达对应系列的筛选列表，游戏默认按 LV 排序；核对方向并切到升序、确认筛选开启、选择首台。强化流程由独立的强化模块维护。 |
| 交付机体 | 从库存底部找合格机体，按委托核对目标与最低等级。默认保护有突破星和 LV60 及以上的机体。只选一台，若需改选先取消原选择；复核同卡选中标记、数量 1/1 和启用的交付按钮。没有合格库存时按目标机体 ID 和作品路线补开发一台，返回原栏重新筛选。出现「获取途径」时沿该单位的开发入口定位，首次开发未完成时按现有流程退出。 |
| 调度资金 | 承接后交付，核对详情金额与确认界面的 CAPITAL 数量。 |
| 委托开发 | 从挑战进入目标作品路线图。按作品基准表选择对应普通分图上的基础机体，复用路线图查找及批量开发流程，核对剩余数量、纯 CAPITAL 总价和余额，返回同一角色确认满额后报告。 |
| 请求出击 | 挑战进入指定作品的关卡页，复用 AP 略过流程，按剩余次数和可用体力执行，回到原委托核实进度。 |
| 夺取单位 | 核对角色、编号、作品和进度。从挑战进入目标作品，在已通关且可夺取的 HARD 3 至 1 按剩余需求略过，每轮每栏最多 90 AP。逐张数结算页绿色「夺取」卡，零掉落继续检查关卡次数及预算。返回原委托核对进度与动作，满额后报告。 |

简中夺取模板均取自 MuMu 原生 1920×1080 画面，坐标为 x、y、宽、高。详情固定字样 `title_capture_unit.png` 裁自 (1404,247,133,33)，搜索区与请求出击一致，阈值 0.96。选关页 `stage_capture_label.png` 裁自 (1337,750,70,36)，在报酬栏上方 (1040,738,550,58) 匹配。奖励卡 `reward_capture_label.png` 裁自 (130,368,67,32)，按十列卡槽逐格核对绿底与字形。两者阈值均为 0.95。连续两帧确认 SKIP RESULT、本批略过次数及相同的夺取卡数量后关闭奖励页。葵丝「夺取单位3」实测：HARD 3 略过三次出现两张夺取卡，委托进度为 2/3；HARD 2 三次均为零张；HARD 1 略过三次出现一张，回到详情为 3/3 和「报告」。绿色字样在独立奖励帧的匹配分数 ≥0.999，红色「隐藏」标签低于 0.75。

特殊委托暂未接入专属执行流程。

### 强化满级与补开发

1. 在单位资料页用两块数字 OCR 分别读当前等级和上限，连续两帧等级及对应按钮一致才操作。等级须为正数且当前值不超过上限。按钮是否亮起、材料区的中文提示、SP 化与 SSP 化均不作为满级证据。
2. 当前值低于上限，进入 LV 强化。按委托剩余量使用 1–5 份材料，计入游戏预选；优先铜，其次银，再用金。缺料则取消并记录该栏失败。
3. 升序首台当前值等于上限，本轮视为现有筛选结果无法强化。返回原委托核对角色、委托 ID 与进度。按作品基准表开发 **一台**，复核作品 Logo、普通分图、目标机体、数量 1、仅 CAPITAL 的费用与余额。交付任务的等级与突破保护只约束交付选机。
4. 消费前按设备、栏位、委托与刷新期记录尝试。同一委托的补开发至多一次。回到角色要求列表后重开原栏，再次确认角色、委托、进度及「挑战」，重新执行升序选机、等级判定和强化。补开发本身不计强化进度；仍满级或补开发未成功则记录失败。
5. 强化成功须回到同一角色核对满额进度和「报告」，再走共用领奖流程。回归应覆盖未满、已满、数字不清、不可开发、补开发后重选及重复消费防护。
