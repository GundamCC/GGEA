# 本机目录与清理约定

`artifacts/` 只用于可运行的发布目录和分发包；不再作为依赖仓库或调试资料夹。
下列目录均被 Git 忽略，源码、默认配置和正式模板仍保存在原来的受版本管理目录。

| 路径 | 用途 | 清理条件 |
| --- | --- | --- |
| `artifacts/publish/`、`artifacts/publish-dev/` | 已生成的可运行程序 | 关闭程序并备份个人配置、自定义模板后可删除 |
| `artifacts/dist/` | ZIP、校验文件与解压验收目录 | 不再需要对应发布包时可删除 |
| `build/` | 编译中间文件、发布暂存、固定提交快照与构建证据 | 无构建运行且不再需要排查证据时可删除；检查失败恢复备份是否仍需保留 |
| `backups/` | 替换发布目录前的完整备份 | 确认旧配置和资源不再需要后可删除 |
| `test-results/`、`logs/` | 测试结果与历史日志 | 不再需要排查证据时可删除 |
| `research/` | 实机截图、模板研究、调试程序与视觉验收资料 | 按资料价值人工选择，不能假设可由编译恢复 |
| `archive/` | 旧实验、旧工具和用途未完全确认的历史资料 | 保留原名与内容，确认用途后再清理 |
| `logs/migration-*.jsonl` | 本次迁移的源路径与目标路径记录 | 用于查找迁移后的旧资料 |

仓库根目录 `dev/` 仍是开发版本入口，`GGEA.ReleaseManager.exe` 仍是发布工具入口。

## 迁移旧布局

运行 `tools/organize-artifacts.ps1 -WhatIf` 可预览，去掉 `-WhatIf` 执行。
脚本不覆盖目标、不删除资料、不移动 `publish/`、`publish-dev/` 和 `dist/`。
每个成功移动的项目写入迁移记录，重复执行不会重复迁移已完成的内容。
旧实验脚本或历史快照可能记录旧绝对路径，保留它们作为历史资料；需要重跑时使用当前 `tools/` 入口。

## 重建运行组件

插件工具链与运行资源在独立扩展仓库维护，不参与主程序构建。

## 实机研究脚本

依赖未公开研究程序的实机采集与扫描脚本不属于公共开发入口，仅保留在被 Git 忽略的 `.local/` 中。普通版、开发版的构建、测试和打包不需要 `research/` 目录或研究 DLL。请勿把整个工作目录压缩后当作源码或产品发行包。
